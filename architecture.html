Component Details

📈 Price Monitor (Core Loop)

  • Runs every 30 seconds via APScheduler
  • Fetches all tickers from Bybit /v5/market/tickers
  • Filters pairs by 24h volume threshold ($25M default)
  • Stores each price in price_snapshots table
  • Routes BTC/ETH → Milestone Engine, others → Percentage Engine

🏆 Milestone Engine (BTC/ETH)

  • BTC: $1,000 steps / ETH: $100 steps
  • Boundary Crossing: Exact detection between consecutive scan prices
  • 241 Trend Filter: Uses 1h lookback (not 24h) to catch dump reversals
  • Direction-Agnostic Lock: Same milestone locked both ways for /time period
  • Multi-level skips: Fire ONE alert, cooldown ALL skipped

🔺 Percentage Engine (All Coins)

  • Default thresholds: [10, 30, 60, 80, 100]%
  • Custom per-symbol: /sol 5,10,15 or /sol 2 (incremental)
  • Model 1: Session-based (00:00 UTC reset)
  • Model 2: Rolling 24h window (default)
  • Fires only HIGHEST crossed threshold, 24h cooldown

🗃 PostgreSQL (9 Tables)

  • price_snapshots — Rolling 24h price cache (48h retention)
  • alert_history — Percentage alert dedup (24h cooldown)
  • milestone_history — Milestone cooldown (direction-agnostic)
  • milestone_last_price — Real-time boundary tracking
  • bot_config — All settings (key-value)
  • session_prices — Model 1 daily baselines
  • custom_thresholds — Per-symbol overrides
  • scanner_logs — Audit trail (7d retention)

☁ Deployment (Railway)

  • Docker container: python:3.11-slim
  • Entry: python -m bot.main
  • PostgreSQL: Railway-managed instance
  • Env vars: BOT_TOKEN, CHANNEL_ID, DATABASE_URL, ADMIN_IDS
  • Auto-restart on crash, health check via Bybit ping
  • Non-root user (botuser) for security

🔄 End-to-End Data Flow

Bybit API → fetch_tickers() → volume_filter → store_snapshot() → route(BTC/ETH vs all) → detect_alert() → check_cooldown() → send_telegram() → record_alert()
